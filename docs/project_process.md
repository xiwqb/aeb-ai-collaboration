# 项目过程与关键判断

本文档根据已保存模型、脚本、运行记录和论文整理，不是逐字聊天记录。阶段顺序用于解释工程依赖，不虚构每一步均由研究者手动完成。

## 任务从能运行变成可验收

最小任务是让50 km/h车辆在前方50 m静止目标坐标之前完成单次制动。AI可以承担接口设计、Simulink搭建、脚本和批量计算；研究者需要明确什么算完成：模型运行结束、坐标间距为正、车速和位移满足运动学关系，并检查2 m预留目标是否真的满足。

先做单次停车，再改变释放条件和初速，使每次异常对应较少的变化因素。点质量文献复现与CarSim车辆联合仿真分开，避免把模型差异误判为算法错误。

## 先给上下文 再让实现落到实际接口

交付给AI的上下文包括软件版本、现有模型、CarSim输入输出通道、运行状态和报错。实现不能仅依据模块名称：Vx输出为km/h，Ax为g，必须转换后用于相应公式。

模型采用所需减速度 `a_req=v²/[2(d−d0)]`，其中 `d=50−Xo`、`d0=2 m`。为避免近距离分母失效，实现包含下限与限幅。50 km/h、50 m条件下理论所需减速度约2.009 m/s²；若直接把50作为m/s输入则约26.042 m/s²。这个数量级检查可以识别单位错误；它不是两次已完成的整车对照试验。

## 制动释放和控制权问题

历史TTC实现出现反复释放的说明和脚本被保留，但当前针对性实验不把它当作前后对照组。当前控制以所需减速度达到5 m/s²为触发条件，固定需求9 m/s²，经1.4增益和0.05 s一阶环节形成制动压力；同时切断油门修正。

保持基线将Relay释放阈值设为−1，窄滞环对照改为4.9，其余入口保持一致。两组首次触发相同而后续切换不同，才支持“释放条件影响制动过程”的判断。研究者需要选择这个能检验解释的对照，而不能把更平滑的一张图直接当作成功。

## 车型和实际生效参数

项目早期说明与当前车辆配置存在差别。最终以装配引用、展开参数和求解器回读为准：当前是X3参数化配置，簧载质量1674 kg，仍含通用部件。文件名、界面名称和一次保存动作不足以证明求解器实际使用了预期参数。

本仓库模型快照与参数摘要对应论文采用的核验组，不混用早期约8.36 m的间距结果；论文的50 km/h保持基线最小坐标间距为6.728096 m。

## 针对性实验形成证据链

六组工况分别检验保持与释放、45/55 km/h初速扰动、零制动压力增益和完全相同配置的重复运行。每组保存实际输入配置、完整采样输出和原生通道，指标来自数据计算。

核验不仅检查最终是否停住，还要看压力是否实际进入车辆、改变一个条件是否产生预期方向的响应、不同输出通道是否按实际单位和采样关系对应，以及相同配置能否复现。

## 文献复现中的结果取舍

简化CCRs复现的触发时刻接近原文，而停车间距未匹配。已保留差异和补充假设，没有为贴合终值不断调整未知参数并宣布完整复现。二次曲线分支的2 m边界也是预设值，不能单独作为成功证据。

## 将过程沉淀到下一次任务

最终保存的是接口约定、固定模型、实验矩阵、原始通道、核验脚本和适用边界。研究者的关键判断落在任务定义、排查依据、实验选择和结论范围；这些判断不能由“AI说可以”代替。AI承担了大量实现及执行工作，具体操作不应被改写为全部由研究者手工完成。
